## Findings

### 1. E is the strongest structured candidate by loop efficiency

`variant-e` has the best structured pipeline-validation rate and lowest average
effective loop count:

- pipeline validation pass rate: 80.6%
- average effective loops: 53.0
- original feature effective loops: 78.1

That supports the current hypothesis that scout-grounded planning can reduce
work churn compared with both scout-only and work-first ordering.

### 2. C is lean and stable, but did not produce the best observed artifact

`variant-c` has the lowest bug+research churn among fixed structured variants:

- bug+research per original source feature: 1.50
- source feature attempts sum: 0

This suggests `scout -> work -> validate` is operationally efficient. The
qualitative report that E produced a better game means raw graph efficiency is
not enough; we need artifact-quality scoring from screenshots/playthroughs.

### 3. F remains a serious baseline, not a strawman

Flat mode completed 8/8 original features and had only 4 infrastructure rows,
but it spawned far more bug work:

- bug tasks: 25
- research tasks: 4
- bug+research per source feature: 3.62
- original feature effective loops: 121.4

Interpretation: flat mode can create strong artifacts, but it appears to push
more correction into downstream bug/integration work. This lines up with run 4
F being strong visually/playably while still expensive.

### 4. G is probably not worth keeping as a mainline candidate

`variant-g` is the weakest quantitative arm:

- lowest terminal completion rate: 91.4%
- lowest pipeline validation pass rate: 63.3%
- highest original feature loops: 134.6
- highest infrastructure rows: 41
- highest diff churn: 664.8 average changed lines per completed event

The work-first chaos-derived order was interesting, but run 7 does not support
keeping it in the next focused comparison.

### 5. Adaptive was respectable, but not clearly superior

Adaptive finished cleanly and had low recovery churn:

- final completion: 96.8%
- bug+research per source feature: 1.62
- original feature effective loops: 82.6

However, it did not beat E on pipeline validation or average effective loops.
It remains interesting as a production strategy, but run 7 does not prove it is
the best research arm.

## Caveats

- Run 7 had provider/router failures. These are counted as infrastructure rows
  and should be censored in deeper statistical tests.
- Wall-clock speed is not primary evidence because all arms shared a fixed
  global agent/provider capacity pool.
- Quantitative telemetry does not yet score playability, screenshot quality, or
  player comprehension. That is the missing measurement layer.
- F uses legacy loop telemetry while structured arms use phase telemetry. The
  analysis compensates with effective loops, but the two modes are still not
  perfectly equivalent.
